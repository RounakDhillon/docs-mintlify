## Requirements
### Metadata
To extract metadata from Microsoft Fabric, you need to authenticate using an **Azure Service Principal**. The Service Principal must have the following:
- A registered Azure AD application with `clientId`, `clientSecret`, and `tenantId`
- The Service Principal must be added as a **member** of the Fabric Workspace containing the Warehouses/Lakehouses to be catalogued
- The Service Principal must have at least **Viewer** role on the Fabric items to read schema and table metadata

To create a Service Principal:
1. Register an application in [Azure Active Directory](https://portal.azure.com/#blade/Microsoft_AAD_RegisteredApps/ApplicationsListBlade)
2. Create a client secret under **Certificates & secrets**
3. Note the **Application (client) ID**, **Directory (tenant) ID**, and the **client secret value**
4. In Microsoft Fabric, go to your Workspace settings and add the Service Principal as a member

You can find more details in the [Microsoft Fabric documentation](https://learn.microsoft.com/en-us/fabric/admin/metadata-scanning-enable-read-only-apis).
### Profiler & Data Quality
Executing the profiler workflow or data quality tests will require the Service Principal to have `SELECT` permission on the tables where the profiler/tests will be executed. More information on the profiler workflow setup can be found [here](/how-to-guides/data-quality-observability/profiler/profiler-workflow) and data quality tests [here](/how-to-guides/data-quality-observability/quality).

## Connection Options
<Steps>
  <Step title="Connection Options">
    - **Host and Port**: SQL endpoint of the Microsoft Fabric Warehouse or Lakehouse (e.g., `your-workspace.datawarehouse.fabric.microsoft.com:1433`).
    - **Client ID**: Azure Application (client) ID for Service Principal authentication.
    - **Client Secret**: Azure Application client secret for Service Principal authentication.
    - **Tenant ID**: Azure Directory (tenant) ID for Service Principal authentication.
    - **Database** *(Optional)*: Name of the Fabric Warehouse or Lakehouse to restrict ingestion to. When left blank, Collate scans all databases.
    - **Driver** *(Optional)*: ODBC driver version. Defaults to `ODBC Driver 18 for SQL Server`.
    - **Ingest All Databases** *(Optional)*: When enabled, ingest data from all Warehouses and Lakehouses in Microsoft Fabric. Can be combined with `databaseFilterPattern`. Defaults to `false`.
    - **Schema Filter Pattern** *(Optional)*: Regex to only include/exclude schemas. System schemas (`db_*`, `guest`, `information_schema`, `sys`) are excluded by default.
    - **Table Filter Pattern** *(Optional)*: Regex to only include/exclude tables that match the pattern.
    - **Database Filter Pattern** *(Optional)*: Regex to only include/exclude databases that match the pattern.
  </Step>

<Tip>
When using a **Hybrid Ingestion Runner**, any sensitive credential fields—such as passwords, API keys, or private keys—must reference secrets using the following format:
```
password: secret:/my/database/password
```
This applies **only to fields marked as secrets** in the connection form (these typically mask input and show a visibility toggle icon).
For a complete guide on managing secrets in hybrid setups, see the [Hybrid Ingestion Runner Secret Management Guide](https://docs.getcollate.io/getting-started/day-1/hybrid-saas/hybrid-ingestion-runner#3.-manage-secrets-securely).
</Tip>
